# WebTools 快速启动器改版设计

**状态：** 对话中已确认设计方向，等待书面设计稿审阅  
**日期：** 2026-09-25  
**项目：** 仅面向 Windows 的 Electron + Vue 3 + TypeScript 桌面效率工具

## 目标与范围

将当前 Nook 改造成名为 **WebTools** 的 Windows 常驻快速启动器。WebTools 在后台运行，通过全局快捷键显示独立的快速搜索窗；现有主界面保留为管理窗口，通过搜索窗右侧的 WebTools 图标打开。

本轮改版包含：

- 系统托盘常驻、独立快速搜索窗和全局快捷键设置。
- 应用发现、启动和搜索质量修复，包括多词首字母匹配、英文别名、拼音检索，以及 Word、ChatGPT、Edge 等应用的覆盖。
- 网址和收藏夹合并到一个网址管理入口，支持网站标题和 favicon 抓取、首字母图标回退、网格和列表布局。
- 可自定义的网页搜索引擎配置。
- Everything 独立文件搜索集成，不参与常规应用搜索。
- 产品品牌改为 WebTools，并将现有界面调整为 Codex 风格的深色桌面界面。

现有 AI 翻译、Google Translate 网页跳转以及 OpenAI／DeepSeek 兼容配置继续保留。本轮不增加通用插件市场。

## 用户体验与界面

### 后台与窗口

- WebTools 运行后驻留系统托盘。关闭管理窗口只隐藏窗口，不退出进程；托盘菜单提供打开管理窗口和退出操作。
- 默认全局快捷键为 `Ctrl+Alt+Space`，在 WebTools 未获得焦点时也能唤出快速搜索窗。
- 快速搜索窗使用独立的轻量 Electron `BrowserWindow`，默认置顶、居中显示。
- 搜索窗空闲时只有输入框和右侧 WebTools 图标；输入后在其下方显示建议列表。
- 点击图标打开现有管理窗口。执行应用或网页搜索后收起搜索窗；Escape 收起窗口。
- 上下方向键切换结果，Enter 执行，鼠标可以选择结果。
- 设置可以配置其他包含实际按键的快捷键。注册失败时保留旧快捷键并显示明确错误。
- 是否启用 Windows 登录后自启动作为设置项提供，默认关闭。

### 搜索结果与命令

- 普通搜索只展示本地应用与 WebTools 保存的网址。
- `?关键词` 将关键词交给当前默认网页搜索引擎，并用系统默认浏览器打开。
- `file:关键词` 进入独立 Everything 搜索模式。
- 应用结果显示图标、名称和“应用”类别，不显示本地文件路径。
- 网址结果显示网站图标、名称和网址域名，可直接打开或点击 `+` 加入收藏夹。
- Everything 文件结果在专用模式中显示文件名和简短父目录，用于区分同名文件；普通搜索结果不混入文件和目录。

### 主管理窗口

- 保留当前管理窗口的外壳和主要页面，以快速搜索、网址管理、翻译和设置作为入口。
- 移除独立“收藏夹”导航项，将收藏夹目录和收藏网站整合到网址管理页面。
- 移除网址页中的“工具”管理标签。实际已安装应用由应用目录搜索；旧的用户工具数据在数据迁移时备份，不继续显示或加入搜索。
- 网址页面以同一网站列表支持“所有网址”和收藏夹过滤，避免常用网址和收藏网站成为重复记录。
- 页面可在网格和列表之间切换，并保存最近布局偏好。
- 网格卡片的图标、标题和卡片区域均可打开网址；列表行的普通区域可打开网址。编辑和删除操作使用独立按钮，不再提供单独的打开箭头。

### Codex 风格

- 采用深石墨色背景，通过略有差异的侧栏、内容区和卡片表面建立层级。
- 使用低对比度细边框、适度圆角和克制阴影。
- 使用柔和绿色／青绿色强调当前选择和主要操作，保持文本对比度和清晰的字体层级。
- 快速搜索窗和管理窗口共享颜色、图标、控件和交互规范；保留 WebTools 自有名称与标识，不复制 Codex 品牌资产。

## 应用发现与搜索模型

### Windows 应用目录

应用目录由主进程建立、缓存并提供显式刷新，不在每次按键时重新扫描。目录适配器按可启动来源整理记录：

1. 用户和公共开始菜单中的 `.lnk`。显示名称优先取快捷方式文件名；快捷方式描述、目标可执行文件名及可获得的程序产品信息作为搜索别名。
2. Windows 注册的桌面应用启动入口。只在可以验证启动目标时创建可启动记录。
3. UWP／MSIX 应用目录。保留应用名称和应用标识，使用 Windows 支持的应用激活方式启动。

一个来源中的坏快捷方式、不可访问目录或损坏元数据不得终止整轮扫描。不同来源按稳定的应用标识去重；应用启动失败时返回可读错误。

应用显示名不得由快捷方式描述单独决定，以避免 IDM 等产品名被自定义文件夹或说明覆盖。产品和文件路径信息只用于别名匹配或内部启动，不作为普通搜索结果副标题。

### 匹配与排序

搜索索引为应用分别维护规范化显示名、拼音、首字母、英文别名、程序文件名和产品元信息别名。`vs code` 按分词匹配 `Visual Studio Code`；中文名称支持汉字、完整拼音和拼音首字母。优先级为：

1. 名称完全匹配和名称前缀匹配。
2. 英文别名、可执行文件名和产品信息匹配。
3. 多词首字母或分词组合匹配。
4. 完整拼音和拼音首字母匹配。
5. 名称及其他别名的包含匹配。

搜索结果只由这些经过整理的应用记录产生，不把 Everything 的任意文件夹结果混入普通应用搜索。这既修复应用发现问题，也避免同名文件夹覆盖真实应用。

## Everything 集成

Everything 是可选的文件／文件夹搜索提供方，不是 WebTools 应用搜索的依赖，也不随 WebTools 安装包捆绑。

- 设置中的独立 Everything 区域展示启用状态、`es.exe` 路径和连接状态，并提供自动探测与手动选择路径。
- 初版通过官方 `es.exe` 查询已运行的 Everything 实例。子进程以参数数组启动，不通过 shell 拼接搜索文本；查询设置超时和结果上限。
- 用户通过 `file:` 前缀显式进入文件搜索。Everything 未安装、`es.exe` 不存在或 Everything 未运行时，仅在该模式显示说明，不影响应用和网址搜索。
- 选中文件后由系统默认程序打开；选中文件夹后在资源管理器中打开。启动路径仅用于这一专用结果和打开动作。
- 搜索输入节流，合并／取消过时请求；初版限制展示结果数，防止高频 IPC 和大量结果影响搜索窗响应。
- 直接 Everything SDK／IPC 适配器留作未来实现选项；只有当命令行适配成为性能或功能瓶颈时再评估。

Everything 官方说明中，ES 命令行可从 Everything 的本机 IPC 查询结果，并要求 Everything 客户端已运行；这支持将其设计为可选提供方，而不是内置应用索引。[ES 命令行](https://www.voidtools.com/support/everything/command_line_interface/) [Everything IPC](https://www.voidtools.com/support/everything/sdk/ipc/)

## 网址、收藏与图标

以单一网站条目保存网址、显示名称、描述、favicon、创建时间及所属收藏夹 ID 列表。一个网站只保存一份，可属于多个收藏夹，也可以不属于任何收藏夹。

- 新增网址时验证 HTTP／HTTPS URL，在主进程获取网站标题和图标。
- 标题解析优先读取页面 `<title>`，失败时保留用户填写名称或使用主机名。
- 图标解析优先读取页面声明的 favicon 链接，其次尝试 `/favicon.ico`；缓存成功的图标数据，失败时由域名首字母生成回退图标。
- 抓取设置连接超时、响应体大小限制和公共目的地址检查；重定向逐跳校验。抓取失败不阻止保存。
- 搜索结果上的 `+` 按钮弹出收藏夹选择器；也可新建文件夹。管理页允许把网址加入／移出文件夹。
- 在没有浏览器扩展的情况下，`+` 按钮可用于 WebTools 内显示的网站结果；任意外部浏览器页面通过粘贴 URL 到管理页收藏。

## 搜索引擎与设置

设置页保留 Google、百度和 Bilibili 内置搜索引擎，并支持新增、编辑、隐藏、拖动排序和设置默认值。

每个搜索引擎有稳定 ID、名称、URL 模板、内置标识、启用状态和排序值。URL 模板包含 `%s` 搜索词占位符，例如 `https://example.com/search?q=%s`。保存时校验 URL 和占位符；打开时按 URL 参数正确编码关键词。内置引擎可以隐藏，但不能删除；自定义引擎可以编辑和删除。

设置页还包括全局快捷键录制、Windows 登录自启动选项、Everything 检测与路径配置、AI 翻译服务配置。快捷键更改先尝试注册新值，成功后再释放旧值；失败时不覆盖现有可用快捷键。

## 数据兼容与迁移

- 产品显示名称、安装包名称和快捷方式显示名改为 WebTools。
- 保持原 Electron `appId` 和用户数据目录标识，避免仅重命名导致用户设置和安全存储密钥丢失。
- 配置 schema 升级至新版本；迁移前备份旧 `nook-data.json`。
- 将旧 `webEntries` 和 `bookmarks` 合并为单一网站集合，依据规范化 URL 去重，保留已有显示名、描述、图标和收藏夹关系。
- 保留收藏夹 ID 和名称。旧收藏如果和普通网址重复，合并到同一条网站记录并关联原收藏夹。
- 旧工具记录从活动设置结构和用户界面中移除，但原配置备份保留，避免升级时不可恢复地丢失。
- 原 AI API 设置和加密 API Key 保持不变。
- 搜索引擎设置迁移为带 ID 的内置及自定义引擎集合，保留当前默认搜索平台。
- 增加全局快捷键、Everything 启用／路径、网格／列表偏好等新设置；不存在时使用默认值。

## 主进程、渲染器与安全

- 主进程拥有托盘、窗口、全局快捷键注册、Windows 应用发现与启动、Everything 子进程、网页 favicon/title 请求和持久化。
- 独立搜索窗和管理窗使用各自的 Vue 路由／入口或由同一 renderer 路由以受控方式呈现；两窗共享搜索与设置服务，但不共享 BrowserWindow。
- 渲染器只调用类型化 preload IPC，不直接访问 Node.js、注册全局快捷键、执行文件或读取密钥。
- 网页抓取限 HTTP／HTTPS、超时和响应大小；限制本机及私网地址并逐跳验证重定向。
- Everything 查询输入通过参数数组传递，不经过 shell；只使用用户明确配置或已检测到的 `es.exe` 可执行文件。
- 快捷键冲突、快捷键不支持、Everything 不可用、应用无法启动和图标抓取失败均提供清晰的用户提示，不导致主窗口或常规应用搜索不可用。

## 验收要点

- WebTools 改名并成功沿用原设置与 AI 密钥；启动后可驻留托盘。
- 在其他应用获得焦点时按 `Ctrl+Alt+Space`，出现输入框式搜索窗；点击图标打开管理窗口。
- 搜索窗支持方向键、Enter、Escape、鼠标选择、网站收藏和 `?关键词` 网页搜索。
- Word、ChatGPT、Edge 等已安装应用可搜索；`vs code` 可找到 Visual Studio Code；`IDM` 优先命中 IDM 应用；普通应用结果不显示本机路径。
- Everything 未配置时应用搜索正常；配置并运行 Everything 后，`file:` 搜索独立返回文件／文件夹并可打开。
- 网址表单自动尝试标题和 favicon 抓取，失败时仍保存并显示首字母图标。
- 网格／列表视图都能通过卡片或列表项打开网址；收藏夹整合到网址页且没有重复的网站记录。
- 设置页可维护自定义搜索引擎和全局快捷键，重启后仍保留。
- 现有 OpenAI／DeepSeek 兼容 AI 翻译和 Google Translate 功能继续可用。

## 验证策略

实现阶段运行 TypeScript 类型检查和 Electron 生产构建，并在 Windows 上手动验收托盘、全局快捷键、应用扫描与启动、UWP 启动、`vs code`／IDM 匹配、Everything 缺失／在线／离线状态、网站 title/favicon 成功与失败、数据迁移和 AI 翻译设置。遵照当前已确认的项目工作约束，不添加或运行自动化测试，除非用户之后明确要求。
