# WebTools 插件平台对标 uTools 开发计划

> 面向后续开发与审核的总体计划。状态：计划稿；本文件本身不代表任何阶段已经实现或完成验收。

**目标：** 在 Windows 上，让 WebTools 用户和插件开发者获得与 uTools 插件平台大体相当的核心体验和功能覆盖，包括普通插件、独立窗口、搜索、超级面板、开发工具与插件分发。具体内部实现允许不同。

**架构：** Rust + Slint 负责启动器、系统交互和超级面板；Electron 负责 Manager 与 Web/Node 插件宿主。继续使用已有 Feature 身份、运行时和通信链路。普通插件通过统一外壳、布局和状态协调形成与搜索框连续的体验；不预设可以直接把 Electron BrowserView 嵌入 Slint。确需改变承载方式时先用小原型验证，再决定实现。

**技术栈：** Windows、Rust、Slint、Electron、TypeScript、Vue、Web/Node、现有 `@webtools/plugin-sdk` 与 `.wtplugin`。

## 1. 目标与边界

1. **体验对齐：** 用户无需理解 Rust 与 Electron 的分工；插件打开、失焦、恢复、返回搜索和分离窗口应自然、统一。
2. **能力对齐：** 本计划列出的 uTools 平台能力均纳入完整路线，按依赖和用户价值分阶段交付；不能把“窗口颜色相同”当作平台对齐完成。
3. **插件开发：** 为插件作者提供稳定声明、上下文、生命周期、搜索、窗口、存储、系统能力、调试和打包能力，并提供真实可用的示例。
4. **设计自由：** 宿主管外壳和公共交互；业务页面可选用 WebTools UI 组件，也可保持自身设计。普通插件默认没有 Windows 系统标题栏；独立窗口使用宿主统一标题头。
5. **兼容边界：** 目标是功能与体验对标，不承诺直接安装 uTools 插件包、逐字兼容 `plugin.json` 或 `window.utools`。若将来要直接兼容，另行设计兼容层和迁移策略；不改变本计划的功能覆盖目标。
6. **性能与资源：** 启动提示是异步反馈，不增加固定展示时间，不串行阻塞 Electron 启动；运行时按真实窗口、后台任务和用户会话管理，不无故常驻。
7. **工作方式：** 以当前实现为基线，先复用再扩展。每个阶段交付可使用的功能和相应示例，按需要做针对性验证；不以文档、无关检查或重复测试替代实现。避免引入与问题无关的防御层和审批流程。

## 3. 产品交互约定

### 3.1 普通插件、独立窗口和翻译

| 操作 | 普通插件：默认模式 | 分离为独立窗口 | Translation 特殊窗口 |
| --- | --- | --- | --- |
| 打开 | 在前台出现，与搜索框位置和视觉连续；不在任务栏显示 | 分离后有任务栏入口，可独立操作 | 按既有独立翻译体验显示在前台 |
| 失焦 | 隐藏，保留当前页面和运行状态 | 窗口继续存在，可处于后台 | 不按普通插件失焦隐藏 |
| 召唤快捷键 | 隐藏后恢复上次普通插件；可见时切换隐藏，再次召唤恢复 | 不把独立窗口误当作临时普通插件；保留已有搜索入口行为 | 保留已验收的独立窗口行为，不强套普通插件循环 |
| Esc | 结束当前普通插件运行并返回**获得焦点**的空搜索框；再次 Esc 关闭搜索框 | 沿用当前独立窗口关闭策略，保证实际回收 | 关闭翻译窗口且不弹出搜索框；不把关闭窗口等同删除翻译设置或禁用服务 |
| 菜单 | 支持分离、退出到后台、结束运行；后台隐藏与真正结束是两种不同动作 | 宿主提供菜单、置顶、最小化、最大化/还原和关闭 | 保留其特殊页签和控制，不强行套普通插件内容 |

Manager 与普通插件统一宿主外观和焦点循环，但不把 Manager 当作第三方插件；具体加载与数据行为仍由 Manager 负责。系统模态对话框、文件选择和用户正在输入时不能被普通失焦逻辑误关闭。

### 3.2 超级面板

选中文字、文件、文件夹、当前目录等只显示实际支持该上下文的功能；例如翻译仅在支持的文本场景出现。点击动作后面板按既有行为关闭，文本、路径和调用来源完整交给插件；无窗口命令可以直接返回面板结果。避免把每个插件都显示成万能动作。

### 3.3 输入和动态结果

插件可以在需要时使用宿主的顶部子输入区；支持占位文字、输入变化、设置内容、焦点切换和移除。插件退出后恢复普通搜索。插件也可以按输入推送可点击的结果列表，例如剪贴板搜索；旧请求的迟到结果不得覆盖新输入结果。未使用这两项能力的插件维持现有打开方式。

## 4. 能力覆盖清单

状态标记：**已有**为源码存在基础；**部分**为有局部能力或限制；**待做**为本次未找到对应公开能力。运行稳定性仍需各阶段验证。

| 能力域 | 状态 | 完整目标 |
| --- | --- | --- |
| 关键词、拼音、别名、排序 | 部分 | 插件/功能名称、别名、图标、搜索高亮和合理排序；动态入口参与相同索引 |
| 搜索框上下文 | 部分 | 文本、文件/目录、图片/截图等按声明匹配，用户选择后传递真实上下文 |
| 超级面板 | 部分 | 文本、文件、文件夹、Explorer 当前目录、可用动作、Quick Result 及精确过滤 |
| 输入匹配 | 部分 | 在已有类型和 `http-url` 基础上支持可表达的正则、数量、文件后缀、活动窗口/应用和可配置匹配；规则及开发错误可解释 |
| 插件内子输入框 | 待做 | 设置/更新/移除输入区；变化回调、焦点与 IME 正确 |
| 搜索框动态结果 | 待做 | 随查询更新的结果、点击/键盘执行、加载/空/错误状态与并发更新 |
| 动态功能入口 | 待做 | 插件按用户配置创建、更新、查询、移除入口；持久化并同步搜索及面板 |
| 生命周期与后台 | 部分 | 初始化、进入、再次进入、隐藏/退出后台、结束及关闭通知；上下文对应当前调用 |
| 自定义窗口 | 部分 | 在已有分离窗口基础上，为插件提供可控窗口创建、尺寸、位置、显示、置顶、通信和关闭 |
| 剪贴板与输入 | 部分 | 文本/图片/文件的复制、读取与按需粘贴到原应用；保持外部焦点语义 |
| 系统/屏幕/交互 | 部分 | 文件与 URL 打开、文件对话框、通知、系统信息、屏幕尺寸、截图、窗口定位、快捷键和模拟输入等 |
| 数据 | 部分 | 插件本地配置、持久数据、文件/二进制、可查询数据与导入导出；升级和卸载的数据行为明确 |
| 定时/后台 | 待做 | 用户开启的周期任务、任务执行、状态和停止；仅有任务时保留必要资源，不用永久常驻替代调度 |
| AI 与 MCP | 部分 | 共享 AI 调用、取消/结果展示；插件声明和注册可调用工具、参数、结果、发现与调用 |
| 浏览器、图片、音视频 | 部分 | 浏览器自动化/外部页面交互、图像处理、音视频处理的可用接口或官方示例；按功能支持说明依赖与平台 |
| 开发工具 | 部分 | 项目创建、框架模板、运行、热重载、调试、日志、模拟各入口、打包、检查与版本诊断 |
| 安装、管理、更新 | 部分 | 本地安装、升级/回退、启停、配置、运行状态、卸载和数据选择；在线发现与更新 |
| 市场与支付 | 待做 | 插件检索、详情、版本、发布、下载、评价、更新；收费/购买/授权能力与服务端流程 |
| 兼容与迁移 | 部分 | WebTools 已安装的 v1/v3 插件、数据和现有调用继续有效；兼容层如需实现另列方案 |

表中“待做”不是要求一次完成所有平台或强制引入全套依赖；它是完整目标的清单。第三方 Node 插件现可作为本地代码使用 Node 能力，不应把受控 SDK 接口误称为操作系统沙箱。

## 5. 分阶段开发任务

### P0：插件宿主一致性与可靠性

**交付：** 在现有 Rust + Electron 架构中修正外壳和真实交互，保留已实现功能。

- [ ] 对照现有搜索框、Manager、普通插件、Translation 的深浅色、布局、圆角、图标、拖动区和按钮命中区，形成共享视觉参数；统一普通/独立插件外壳与 Manager 标题头。
- [ ] 协调搜索框与插件窗口几何、缩放、显示和焦点；验证搜索入口、展开卡片和超级面板入口，避免闪烁、错位或多余空白。不要因为动画等待而推迟 Electron 启动。
- [ ] 按第 3 节检查并修复默认/分离模式、任务栏、失焦、快捷键切换、Esc 返回、面板入口和 Manager 交互；回到搜索框必须能继续键盘输入和 Esc 退出。
- [ ] 核对窗口/进程回收：隐藏仍保留状态；结束运行销毁该运行实例；其他窗口、任务和已安装 Everything 不被误关；无拥有者时沿用已有协作式退出。
- [ ] 提供一个复用的测试插件包，包含窗口、输入框、计数状态、文本/文件动作和分离按钮；后续阶段在同一插件上扩展，只有新功能不能覆盖时才新增插件。

**主要位置：** `electron/plugins/plugin-window-manager.ts`、`electron/renderer/plugin-window-chrome.*`、`electron/renderer/plugin-window-menu.*`、`electron/services/` 的 Native 通信、`native-rs/prototype/slint-launcher/src/app.rs` 与对应 Slint UI。实际修改前核对现有调用，不重建一套并行窗口管理器。

**完成表现：** 用户能在真实 Windows 中重复完成打开→失焦→召回→Esc→搜索框→Esc；搜索、展开、面板和 Manager 入口一致；分离窗口可以独立使用且任务栏正确。

### P1：统一插件 UI 与主题

**交付：** 设计令牌、可选插件 UI 基础样式/组件、真实样例。

- [ ] 合并宿主外壳和插件可消费的颜色、字体、间距、图标、圆角、焦点样式；确认深浅色与高 DPI 的有效值。
- [ ] 提供可选的基础样式/组件：容器、按钮、输入、开关、列表、标签、菜单、提示、加载、空状态和错误状态；兼容 Vanilla、Vue、React、Svelte 的普通 Web 使用方式。
- [ ] 更新 SDK starter 默认引入统一样式；允许作者自行覆盖或不使用，旧插件不因未采用 UI 包而失效。
- [ ] 扩展 P0 测试插件，覆盖主题切换、长文字、中英混排、窄窗口、键盘焦点和常用缩放。

**主要位置：** `plugin-sdk/declarative-v1/web/theme.css` 和新增 UI 样式/组件入口、`plugin-sdk/create-webtools-plugin/`、`docs/plugin-window-theme-contract.md`、`examples/plugins/`。

**完成表现：** 默认新插件与宿主在深浅色下看起来属于同一产品；自定义样式插件仍保持自身页面。

### P2：插件内搜索与动态结果

**交付：** 插件可使用统一子输入区和主搜索结果列表；实现一个真实搜索型插件示例。

- [ ] 在 Feature 会话上建立宿主输入区控制：申请/移除、占位文字、设置和读取文本、获得/释放焦点、输入变化事件；文字输入、中文 IME 和 Esc 行为正确。
- [ ] 增加与当前查询绑定的动态结果：标题、描述、图标、稳定结果身份、键盘/鼠标选择、加载/空/错误状态。重复输入时只显示当前结果，不阻塞原有静态搜索。
- [ ] 将输入和结果跨 Rust/Electron 通信接入当前 Feature 身份及生命周期；隐藏、结束、断开时关闭该会话，不能串到下一个插件。
- [ ] 使用剪贴板搜索或具备本地数据的测试功能演示：进入后直接在顶部输入、逐字更新结果、Enter 打开、Esc 回到启动器；同时保持普通插件无需接入此能力。

**主要位置：** `src/shared/feature-contracts.ts`、`electron/services/feature-invocation-service.ts`、`electron/plugins/web-host-capabilities.ts`、`plugin-sdk/declarative-v1/web/`、`native-rs/crates/webtools-ipc/`、`native-rs/prototype/slint-launcher/src/app.rs` 和 `ui/`。

**完成表现：** 输入“剪贴板”进入后可以在同一顶部输入区搜索并操作结果；连续输入与中英文切换没有旧结果回跳。

### P3：动态入口与上下文匹配

**交付：** 插件可以声明和维护真实可用的功能入口，并准确出现在相应场景。

- [ ] 扩展现有 `FeatureRef` 和 `acceptedContexts`，覆盖图片/截图、选中文件/目录、当前 Explorer 目录、活动窗口、文本规则及可描述的数量/扩展名条件；保留既有契约的解析与默认行为。
- [ ] 支持插件根据用户设置创建、更新、列出和删除动态功能，持久化、卸载清理，并实时更新 Launcher、Super Panel 和 Manager 投影。
- [ ] 支持无界面动作与窗口动作共享匹配结果；调用时携带原始上下文、入口来源和 Feature 身份。
- [ ] 扩展测试插件：图片处理只匹配图片；文件夹操作只匹配文件夹；文本搜索只匹配文字；用户创建的快捷功能可搜索、执行、修改和删除。

**主要位置：** `plugin-sdk/declarative-v1/runtime-v3/manifest-v3.mjs`、`manifest.schema.v3.json`、`electron/plugins/feature-registry.ts`、`electron/services/native-plugin-projection-publisher.ts`、`native-rs/crates/webtools-ipc/src/projection*`、`native-rs/prototype/slint-launcher/src/panel_model.rs`。

**完成表现：** 功能只在正确上下文出现；更新动态入口后无需重启即可搜索；旧插件原有动作继续可用。

### P4：生命周期、窗口和常用系统能力

**交付：** 可供第三方开发的完整基础能力，而不仅是宿主内部操作。

- [ ] 提供初始化、进入、再次进入、隐藏/退出后台、结束/关闭的 SDK 通知与取消订阅；相同窗口被再次激活时送达新的上下文。
- [ ] 支持必要的自定义窗口：创建、显示/隐藏、调整尺寸和位置、置顶、消息通信及关闭；主窗口/独立窗口/插件业务子窗口身份和归属清楚。
- [ ] 增加常用桌面能力：选择文件或目录、打开文件/目录/HTTP(S)、系统通知、剪贴板文本/图片/文件、向原前台应用粘贴或输入、屏幕信息及截图。与现有 Node 能力明确边界。
- [ ] 面向快捷操作增加应用级快捷入口和按需模拟输入；失焦恢复和外部输入以真实 Windows 交互验证。
- [ ] 文档同时解释 API、何时使用、插件退出时资源行为与示例；旧 SDK、旧 Manifest 和已有配置不因新增接口失效。

**主要位置：** `plugin-sdk/declarative-v1/web/`、`node.d.mts`、`electron/plugins/web-host-capabilities.ts`、`electron/plugins/plugin-window-manager.ts`、现有 Native 通信实现。

**完成表现：** 插件在不依赖私有宿主接口的情况下，完成打开文件、选中内容处理、复制/粘贴和自定义窗口样例；反复进入和退出不丢失或混淆上下文。

### P5：插件数据、后台任务、AI 与扩展能力

**交付：** 与 uTools 常见高级插件相当的可组合能力。

- [ ] 在已有 config 和 JSON storage 上补齐可用的数据读写、二进制/文件、查询、备份导入导出，以及升级/卸载保留规则；区分插件数据和共享凭据。
- [ ] 增加由用户开启的定时任务和后台触发：任务登记、执行、取消、失败展示、退出与重启后的处理；避免以 Electron 永久常驻代替任务设计。
- [ ] 在现有 Shared AI 上补齐实际需要的结果、取消和配置体验；支持插件声明可发现的工具、参数及结果，接入 MCP/Agent 调用。
- [ ] 支持浏览器自动化、图像与音视频工作流：明确哪些使用 Node/插件依赖，哪些由宿主提供稳定接口；提供真实示例与错误反馈，不强制所有插件携带大依赖。
- [ ] 样例覆盖：定时提醒、共享 AI 命令、注册一个 MCP 工具、图片或音视频处理、受控网页自动操作。

**主要位置：** `electron/plugins/` 的现有 capability 与 store、`electron/services/`、`plugin-sdk/`、`src/features/plugins/`、`native-rs/` 的调度/系统集成。具体 API 名称在实现前结合 SDK 现状确定并写入正式类型定义。

**完成表现：** 安装的示例在重启后保留数据，能按用户设定执行任务，AI/MCP 能传递实际输入并返回结果；插件退出后不遗留无主工作。

### P6：开发工具、文档与版本兼容

**交付：** 外部开发者不依赖 WebTools 源码即可完成开发和交付。

- [ ] 统一 SDK、生成器、模板与文档版本；说明 Electron/Node ABI、Manifest、插件包和最低宿主版本。
- [ ] 完善创建、启动、热重载、断线重连、日志/报错、验证、打包、安装和更新流程；开发模式能模拟 Launcher、面板、文件与文字入口。
- [ ] 给 Vanilla/Vue/React/Svelte 提供最小可运行模板；覆盖普通窗口、子输入和动态结果、文件上下文、无界面命令、自定义窗口与统一 UI。
- [ ] 保留 v1/v3 已安装插件和用户数据，变更字段或 API 时提供默认行为与迁移说明；不把现有插件强制改成新模板。
- [ ] 输出完整作者文档：快速开始、Manifest、SDK API、上下文、生命周期、视觉、调试、分发、常见错误及实际示例。

**主要位置：** `plugin-sdk/create-webtools-plugin/`、`plugin-sdk/declarative-v1/`、`electron/plugins/plugin-development.ts`、`src/features/plugins/PluginDevelopmentPanel.vue`、`docs/plugin-development.md`、`examples/plugins/`。

**完成表现：** 从仓库外新建项目，完成开发、修改、热重载、打包、安装、升级和卸载，不需要复制 WebTools 仓库内部代码。

### P7：插件市场、分发、更新与商业能力

**交付：** 在已有本地插件管理之上，实现面向用户和作者的在线生态。

- [ ] 产品端：搜索、分类、详情、截图、作者、版本、依赖/兼容信息、安装进度、更新和卸载；继续支持本地包和离线使用已安装插件。
- [ ] 作者端：上传、版本管理、发布说明、兼容范围、撤回和问题反馈；定义包格式、存储、下载地址与客户端交互。
- [ ] 服务端：插件目录、包分发、版本元数据、账号/作者身份、基础运营和故障处理；明确服务归属和部署成本。

## 6. 端到端验收场景

1. **普通插件：** 从搜索打开→前台显示且无任务栏图标→失焦隐藏→快捷键恢复原内容→Esc 返回聚焦搜索框→再 Esc 关闭。
2. **分离插件：** 菜单分离→出现任务栏入口→置顶/最小化/最大化/恢复→失焦仍存在→关闭后该运行实例退出。
3. **Manager 与 Translation：** Manager 符合既有搜索框焦点循环；Translation Esc 直接关闭且不召唤搜索框。菜单、主题、拖动和 DPI 与当前产品体验一致。
4. **搜索型插件：** 中文 IME 和英文输入、连续输入、结果键盘选择、无结果、慢结果返回及退出时清理均正常；加载提示不增加固定启动等待。
5. **超级面板：** 选中文字、图片、文件、文件夹及 Explorer 目录分别只显示匹配功能；点击后带入正确数据；翻译和无界面动作能正常运行。
6. **动态功能：** 插件创建/修改/删除一个入口，搜索和面板及时反映；重启后应保留的入口仍存在，卸载后不再出现。
7. **插件作者：** 外部项目创建、开发热重载、调试、打包、安装、升级、卸载和数据选择完整可用；既有 v1/v3 插件仍可使用。
8. **常用能力：** 复制/粘贴、选择和打开文件、通知、自定义窗口、存储、AI 与定时任务有真实可运行示例；异常时用户能理解原因并继续操作。
9. **市场：** 在线发现、安装、更新及离线运行；商业功能只有完整接入后才对外展示。
10. **长时间使用：** 多次打开/隐藏/恢复/结束和多插件切换后，不出现窗口卡死、任务栏残留、错误焦点或无主插件进程。记录真实发现的问题，不用增加固定等待来掩盖。

## 7. 实施顺序与交付方式

按 **P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7** 推进。P1 的视觉资源和 P2 的输入交互可在 P0 稳定后结合样例迭代；每阶段完成后交付可安装的预览包和对应可复用插件包，说明本次改变、使用方式和实际验证。无需每一次小改都另做插件包。

每阶段开始前阅读本计划及当前实现，必要时为该阶段补充简短的实现细节；不得把“编写下一份计划”当成该阶段的功能交付。若某能力受 Windows、现有技术或服务端条件限制，交付可用部分并如实记录限制，后续继续完成对应条目，不把它悄悄从对标范围删除。

## 8. 需要在对应阶段确定的产品细节

- 在线市场的服务器、账号、作者审核、商业模式和支付接入是产品及服务端工作；P7 开始时根据实际资源确定，不影响 P0–P6 开发。
- uTools 的直接插件二进制/API 兼容属于独立扩展；本计划目标为能力与体验对齐，先保证 WebTools 原生插件平台完整。
- 截图、模拟输入、浏览器自动化及后台任务需要明确可见行为和用户选择；优先复用现有系统接口，避免平白增加重复设置。
- 目前“ES 命令行工具”设置与 Rust 文件搜索现状不一致，可在相关设置整理时删除误导性的 ES 控件；保留内部自动识别可用 Everything 的能力。此项与本计划的插件窗口实现互不阻塞。
