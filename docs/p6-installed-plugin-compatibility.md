# 已安装插件与用户数据兼容

WebTools 宿主升级沿用原用户资料目录，通过已安装的包记录恢复插件。Manifest v1 继续走声明式页面和动作运行时。Manifest v3 继续用该包自带的 Web 或 Node 运行时文件及原有权限。宿主不根据当前 SDK 或生成器版本重建包。内置翻译由宿主注册，随产品版本发布。

| 用户或作者操作 | 兼容行为 |
| --- | --- |
| 升级 WebTools | 用同一资料目录保留插件包、插件 ID、启用状态和已有权限。宿主仍会校验包、最低宿主版本及原生 ABI。 |
| 更新同 ID 的插件 | 通过正常安装并确认更新。插件私有 JSON、文件和 Node 数据沿用同 ID 的存储。v3 浏览器存储的来源也基于插件 ID。 |
| 增加一个设置 | 保持旧键和类型不变，给新键指定默认值。v3 的可兼容增补继续使用原 `configuration.schemaVersion`。读取配置时为缺失键补默认值，已有值继续使用。 |
| 删掉或重命名设置，更改类型、缩紧限制或升级 v3 配置结构版本 | 发布前设计并说明转换方法，保留旧数据的备份或导出。宿主不会猜测旧键含义。v1 拒绝与现存设置不兼容的包更新。v3 保留原配置，向用户显示不兼容状态；显式重置前会备份原配置。 |
| 作者主动把同 ID 的 v1 插件升级成 v3 | 同 ID 的插件私有 JSON 可继续访问。v1 与 v3 的设置文件分开，v3 从自己的默认值开始，权限重新授权。若新版需要旧设置，作者应提供明确的导入流程。 |
| 新增可选 SDK 能力 | 根据目标宿主、Manifest 和授权启用，按文档判断功能可用性。对旧宿主提供原入口或无副作用的降级行为。不要把工具链版本当成可用能力的判据。 |
| 卸载与重装 | 选择保留数据后安装同 ID 的包可恢复数据。只有用户选择删除数据，才会移除该插件自己的存储。 |

对于本轮增补字段，`compact` 的默认值是 `false`，原 `label` 与便笺值保留。这个例子没有改变宿主协议或存储格式，正常升级无需迁移工具。

## 验证证据

`scripts/verify-p6-installed-compatibility.mjs` 使用 11 月 16 日与 11 月 18 日交付中的两个不同打包版 Manager，共用隔离资料。先在旧宿主通过实际插件 API 安装并写入 v1、v3 验收样例，再正常退出。在当前打包版里不重装就检查包、授权、启用状态及原值。随后分别测试同 ID 更新、保留数据重装与显式删除。v3 示例捆绑已验收 1.18.0 插件包内的 SDK 1.15.0 网页接口文件。

结果为 7 项打包版兼容检查通过，另有 75 项现有定向测试通过。打包比较使用便携版 Manager 和独立资料，未运行正式安装器或覆盖日用资料。完整预览、验收插件和证据位于桌面 `webtoolstest/P6-Compatibility-20261118-r1`。
